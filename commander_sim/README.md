# Package extraction, first seam

`ServiceRegistry` validates unique names, dependencies, and cycles before constructing any service. Each `build()` calls factories anew and returns a read-only service mapping; factories remain responsible for producing independent mutable state. Dependencies are passed as read-only mappings. The registry is deliberately independent of particular cards, decks, and legacy imports.

`commander_sim.legacy.run(deck='premium', seed=0, rounds=8)` invokes the existing CLI in a separate interpreter and returns its JSON result. Subprocess isolation prevents the historical modules' unqualified names and `sys.path` manipulation from contaminating the caller. This is a compatibility adapter, not an in-process migration or an implementation of multiple detailed decks. It does not yet expose game objects, policy injection, or an event stream.

Run package contracts with `python -m unittest discover -s tests -q`; the repository's `run_all_tests.py` also runs them. The next extraction should move a real service behind a narrow interface and compare it against the saved replay baselines before changing the live engine.

`commander_sim.decks.DeckProvider.bundled()` validates the saved premium and budget presets, or a local file passed to `load(path)`, against the repository's identity snapshots. It checks a single Magnus commander, 100 cards, singleton constraints across zones, Commander legality and UR color identity; missing or incomplete metadata fails closed. A declared face-name alias is checked against the snapshot's card faces. The CLI passes the validated composition to the same current engine for both presets and `--deck-file`; this does not establish effect coverage. New cards require verified metadata before this provider accepts them. Sectioned Flameslinger-style lists and exact Oracle Adventure names are recognized; declared section totals are checked. Only Magnus is supported. The active engine still relies on historical, deck-specific card installers and metadata tables; this is an injection seam, not full engine extraction.

`commander_sim.snapshots` validates the saved v0.7 fixture against its matching offline snapshot without invoking the engine. The snapshot includes verified identities and printed data; it does not certify effect implementations. The live simulator is still restricted to its bundled legacy identity set.

`commander_sim.queries` provides conservative three-valued predicates and a view of existing kernel objects. Fabricate and wizardcycling use these type/subtype predicates; target restriction checks are partial and return unknown unless completeness is explicitly established. Power and mana value are unknown unless a caller supplies verified information. This is an initial seam, not the complete universal characteristics layer.

`commander_sim.observation` provides a separate deterministic deck projection, not a game engine. It keeps the opening seven, draws once each turn for a non-starting seat, plays only basic Islands/Mountains, and labels spells passing a total-mana-value screen as candidates. It neither checks full casting legality nor resolves spell effects or responses. See `simulator/card_data/OBSERVATION.md` for a reproducible fixture and measured runtime.
