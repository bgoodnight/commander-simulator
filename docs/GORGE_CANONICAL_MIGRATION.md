# Commander simulator migration: gorge canonical backend

**Decision (2026-11-03):** gorge is the sole **future gameplay simulation
backend**. The previous Python rules kernel, abstract opponent policies,
simulated turn runs, and legacy replay exports are preserved as a read-only
development archive, not the source for new Commander win rates or gameplay
claims.

## Boundaries

- **Canonical gameplay**: `commander_sim/gorge_backend.py` launches the
  pinned Go gorge rules kernel, which provides all four real Commander decks,
  legal actions and native AI pilots. Simulator run outputs must identify
  `engine=gorge`, source commit, seeds, decks and pilot policy.
- **Rich replay**: the raw `gorge-native-trace-v1` log remains canonical.
  Physical `gorge-physical-state-v1` adds game-specific object identities
  and turn-boundary snapshots captured from gorge's live state. It is
  NOT a reconstructed Python game or an end-of-turn state.
- **Reusable catalog**: existing pinned Scryfall oracle/printing metadata
  provides stable card art and names; forge-corpus identities are pinned
  to the selected version. Object IDs are regenerated per game.
- **Historical engine**: `commander_sim/early_game_runner.py`,
  `commander_sim/opponent_stress.py`, `commander_sim/pilot_policy.py`,
  `commander_sim/shared_effect_registry.py`, and supporting reviewed
  modules remain on Git and can still pass regression tests, but must not
  power newly published game outcome or deck-power metrics.
- **Historical simulations**: existing files under `simulator/`,
  `web/pages/data/`, `docs/deck-lab/`, and archived outcome files retain
  their old provenance. The UI labels these as historical/legacy, never as
  gorge gameplay. Preserve all original run seeds and logs for comparison.

## Migration checkpoints

1. Build/load a small real gorge precon pod and verify full legal gameplay.
2. Export exact physical card identities, zone snapshots and source event
   logs for a few seeds; reject inconsistent snapshots in CI.
3. Retrofit the existing four-player UI to display those snapshots while
   continuing to support legacy archived runs through a separate disclosure.
4. Audit card interactions and player decisions from replay examples.
5. After those checks, run larger gorge-only datasets to fill the canonical
   outcomes, card analytics, matchup and insights panels. Never publish
   old Python results as if they were generated by gorge.

The migration is intentionally incremental: a UI panel that still uses
legacy data must be marked **archive**, not silently substituted.
Do not delete code, pinning data or historical observations as part of
this migration; the Git history and archived samples make regression
investigations possible.

## Privacy and licensing

Source logs contain hands and hidden library order, so keep raw snapshots in
restricted per-run artifacts. No Forge script corpus is redistributed.
A future public UI export must be specifically sanitized and validated.
